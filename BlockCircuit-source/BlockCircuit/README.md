# Block Circuit — .NET 복셀 샌드박스

C# / .NET 8 + Raylib로 만든 싱글플레이 3D 게임입니다. 광질, 블록 건축, 레버·전선·램프 회로를 지원합니다. 마인크래프트에서 영감을 얻은 독립 프로토타입이며, 원작의 코드나 리소스를 사용하지 않습니다.

이번 버전은 **설치 가능한 블록을 8종에서 178종으로 확장**했습니다. 새 블록 170종, 검색과 분류를 지원하는 블록 라이브러리, 재질별 절차적 픽셀 텍스처를 추가했습니다. 새 월드에서는 모든 설치 가능한 블록을 128개씩 지급합니다.

엔진의 P0 단계에서는 월드 데이터를 16×16×16 청크로 나누고, 변경된 청크만 다시 만드는 GPU 메시 캐시와 그리디 메시 병합을 적용했습니다. 플레이 가능한 월드 크기는 40×28×40으로 유지합니다. 구조와 검증 방법, 후속 단계의 범위는 [ENGINE-NOTES.md](ENGINE-NOTES.md)에 정리했습니다.

추가 개발에서는 **고정 60틱 시뮬레이션, 변경된 회로망만 갱신하는 회로 계산, 실행 취소·다시 실행, 충돌이 적용되는 비행과 설정 화면**을 제공합니다. 퀵바 구성과 화면·마우스 설정도 다음 실행에 유지됩니다.

## Windows 실행

`BlockCircuit-windows-x64.zip`을 **전체 압축 해제**하고 `BlockCircuit.exe`를 실행하세요. .NET을 별도로 설치할 필요가 없습니다. Windows x64와 OpenGL 3.3을 지원하는 그래픽 환경이 필요합니다. Windows 배포본은 교차 빌드하며, 실제 Windows에서의 실행은 검증하지 않았습니다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD / 마우스 | 이동 / 시점 |
| Space / 왼쪽 Shift | 점프 / 빠르게 이동 |
| 왼쪽 마우스 누르고 있기 | 광질; 재질마다 걸리는 시간이 다름 |
| 오른쪽 마우스 | 선택한 블록 설치 |
| 1–8 / 마우스 휠 | 퀵바 슬롯 선택 |
| 가운데 마우스 버튼 | 바라보는 블록을 현재 퀵바 슬롯에 지정 |
| Tab | 블록 라이브러리 열기/닫기 |
| E | 바라보는 레버 켜기/끄기 |
| Ctrl+Z / Ctrl+Y | 마지막 편집 실행 취소 / 다시 실행 |
| F | 비행 모드 켜기/끄기; 블록과 충돌 유지 |
| 비행 중 Space / 왼쪽 Ctrl | 상승 / 하강 |
| F3 | 엔진 디버그 정보 표시/숨기기 |
| F4 | 회로 디버그 정보와 신호 세기 표시/숨기기 |
| F5 / F9 | 월드 저장 / 불러오기 |
| F10 | 설정 화면 열기/닫기 |
| Esc | 열린 화면 닫기 또는 일시정지/재개 |
| 창 닫기 | 자동 저장 후 종료 |

블록 라이브러리를 열면 이동과 광질이 일시정지됩니다. 아래 슬롯을 클릭하거나 검색창에 입력 중이 아닐 때 **1–8**을 눌러 교체할 슬롯을 선택한 뒤, 원하는 블록을 클릭하세요. **Tab / Esc / CLOSE**로 닫으면 선택한 블록을 설치할 수 있습니다. 슬롯 지정은 수량을 늘리지 않으며, 설치할 때 하나씩 소비하고 캐면 다시 회수합니다.

왼쪽 분류 버튼으로 재질을 고르고, 검색창을 클릭해 **영문 블록 이름**을 검색할 수 있습니다. 예를 들어 `diamond`, `cherry`, `blue`를 입력해 보세요. 검색은 현재 분류 안에서 이루어지므로 전체에서 찾으려면 `All blocks`를 선택합니다. 마우스 휠, `PREV` / `NEXT`, 또는 검색창에 입력 중이 아닐 때 **PageUp / PageDown**으로 페이지를 넘깁니다.

실행 취소는 성공한 **광질·설치·레버 조작을 최대 128회** 기억합니다. 받침을 캐면서 함께 회수한 전선·레버와 인벤토리 수량도 같은 작업으로 복원합니다. 새 편집을 하면 다시 실행 기록이 지워지고, 월드를 불러오면 두 기록이 모두 초기화됩니다. 플레이어 몸 안에 블록을 복원하는 작업은 거부됩니다. 편집 기록은 게임을 종료하면 사라집니다.

## 화면·조작 설정

**F10**에서 목표 FPS(30/60/120/144/무제한), 시야각(60–100도), 마우스 감도, 그리기 거리(32–128블록)를 바꿀 수 있습니다. 기본값은 60 FPS, 시야각 72도, 감도 1.00배, 그리기 거리 64블록입니다. 감도 조정 범위는 0.40–2.40배입니다. FPS 설정과 관계없이 이동·광질·설치·회로 변경은 초당 60틱으로 처리합니다.

설정 변경은 즉시 적용됩니다. **SAVE**를 누르면 설정과 퀵바 8칸·선택 슬롯을 월드 파일과 같은 폴더의 `settings.json`에 보관합니다. F5 또는 정상 종료 시에도 월드와 함께 저장합니다. **RESET DEFAULTS**는 설정과 퀵바를 기본값으로 되돌립니다. 설정 파일이 없으면 기본값으로 시작하고, 읽을 수 없거나 형식이 잘못된 경우에는 기본 설정으로 시작하며 안내를 표시합니다.

## 블록 라이브러리

공기와 설치할 수 없는 기반암을 제외한 **178종**이 준비되어 있습니다.

| 분류 | 종류 | 대표 블록 |
|---|---:|---|
| Natural | 14 | 잔디, 흙, 모래, 붉은 모래, 자갈, 점토, 눈, 얼음, 진흙, 이끼, 균사체 |
| Wood | 24 | 참나무·자작나무·가문비나무·정글·아카시아·짙은 참나무·맹그로브·벚나무의 원목, 판자, 잎 |
| Stone | 39 | 돌, 조약돌, 석재 벽돌, 화강암, 섬록암, 안산암, 심층암, 흑암, 사암, 흑요석, 석영, 프리즈머린 |
| Ores | 22 | 석탄·철·구리·금·레드스톤·청금석·다이아몬드·에메랄드·석영 광석, 광물 블록, 산화 단계별 구리 |
| Glass | 17 | 투명 유리와 16색 유리 |
| Wool | 16 | 16색 양털 |
| Concrete | 16 | 16색 콘크리트 |
| Terracotta | 16 | 16색 테라코타 |
| Decor | 11 | 호박, 수박, 건초 더미, 스펀지, 발광석, 바다 랜턴, 벌집, 꿀, 슬라임, 마그마, 자수정 |
| Circuit | 3 | Signal Wire, Lever, Circuit Lamp |

목재 결, 벽돌 줄눈, 광석, 직물 등은 게임이 생성하는 텍스처로 구분됩니다. 일반 재료와 장식 블록은 정육면체 건축 블록입니다. 모래·자갈의 낙하, 얼음의 미끄러짐, 슬라임의 반동, 꿀의 끈적임, 마그마의 피해, 스펀지의 물 흡수, 구리의 자동 산화는 구현하지 않았습니다. 발광석과 바다 랜턴은 밝은 외형의 장식이며 주변을 비추는 동적 조명은 없습니다. 레드스톤 광석은 광질용 블록이며 회로 신호는 `Circuit` 분류의 부품을 사용합니다.

## 월드와 저장

40×28×40 크기의 월드에 지형과 지하 통로가 생성됩니다. 새 월드에는 다양한 광석과 나무도 생성됩니다. 플레이어에게 중력과 블록 충돌이 적용되며, 바닥 기반암은 캘 수 없습니다.

저장 파일이 있으면 시작할 때 자동으로 불러옵니다. F9를 누르면 마지막 저장 상태로 돌아가고, 창을 닫으면 현재 상태를 자동 저장합니다.

저장 위치는 Windows의 `%LOCALAPPDATA%\BlockCircuit\world.json`, Linux의 `~/.local/share/BlockCircuit/world.json`입니다. 정확한 위치는 .NET의 `LocalApplicationData` 경로를 따릅니다.

같은 폴더의 `game.log`에는 저장 결과나 설정·불러오기 오류를 기록합니다. 오류 안내가 나오면 이 파일로 원인을 확인할 수 있습니다.

**이전 버전의 저장 파일도 불러올 수 있습니다.** 기존 지형, 블록 수량, 회로와 플레이어 위치를 유지하면서 새 블록 170종을 각각 128개씩 지급합니다. 기존 월드의 지형은 다시 생성하지 않으므로 새 광석과 나무의 자연 생성은 새 월드에 적용됩니다. 새 지형으로 시작하려면 게임을 종료하고 `world.json`을 다른 이름으로 옮겨 보관한 뒤 다시 실행하세요. 퀵바 구성은 별도의 `settings.json`에서 유지합니다.

청크 엔진에서도 기존 v1/v2 저장 형식과 블록 ID를 유지합니다. 저장할 때 기존 배열 형식의 스냅샷을 만들고, 불러올 때 청크로 복원합니다. v1에는 새 블록의 초기 수량을 추가하며 v2의 기존 수량은 그대로 복원합니다.

## 회로 만들기

1. 평평한 땅 위에 `Lever`를 설치합니다. 기본 퀵바의 7번 슬롯입니다.
2. 레버 옆에서 `Signal Wire`를 이어 설치합니다. 기본 퀵바의 6번 슬롯입니다.
3. 전선 끝에 `Circuit Lamp`를 설치합니다. 기본 퀵바의 8번 슬롯입니다.
4. 레버를 바라보고 **E**를 누르면 전선과 램프가 밝아집니다.

시작 위치 앞에 예제 회로가 있습니다. 레버는 신호 15를 발생시키고, 전선/램프 한 칸마다 신호가 1 감소합니다. 신호는 면을 맞대는 상하좌우앞뒤 이웃으로만 전달됩니다. 대각선 연결이나 일반 블록을 통한 전도는 없습니다. 램프는 신호를 받지만 전달하지 않습니다. 전선·레버는 바로 아래에 단단한 블록이 필요하며, 받침을 캐면 회수됩니다. 단선하면 연결되지 않은 부분은 즉시 꺼집니다.

현재 회로는 레버·전선·램프의 기본 회로입니다. 피스톤·리피터·비교기·제작·몹·멀티플레이·무한 월드는 포함하지 않습니다.

## 소스에서 실행 및 검증

.NET 8 SDK를 설치하고 이 폴더에서 실행합니다.

```bash
dotnet run -c Release
```

Linux는 데스크톱 디스플레이와 OpenGL/X11 관련 라이브러리가 필요합니다. Windows/Linux x64를 대상으로 하며, macOS에서의 실행은 검증하지 않았습니다.

```bash
dotnet build -c Release
dotnet run -c Release -- --self-test
dotnet run -c Release -- --engine-tests
dotnet run -c Release -- --gameplay-tests
dotnet run -c Release -- --benchmark
dotnet run -c Release -- --circuit-benchmark
```

기존 자동 검사 45개는 블록 목록, 전체 블록 설치·채굴, 인벤토리, 검색·분류, 회로 전파·감쇠·단선·복구, 받침 제거, 기반암, 레이캐스트, 지형 생성과 저장 복원을 확인합니다. `--engine-tests`의 검사 41개는 청크 경계와 변경 전파, 메시, DDA 레이캐스트와 저장 호환성을 확인합니다. `--gameplay-tests`의 검사 48개는 고정 틱, 이동·비행, 편집 이력, 회로와 설정을 확인하며, **총 134개 검사가 통과**했습니다. 실제 OpenGL 게임플레이 통합 검사 9개도 통과했습니다.

`--benchmark`는 CPU 메시 생성과 편집 부하를 `benchmark-results.json`에, `--circuit-benchmark`는 회로 계산 부하를 `circuit-benchmark-results.json`에 기록합니다. CPU 벤치마크와 실제 GPU의 FPS 측정은 구분합니다. 검사 결과와 측정 범위는 [엔진 노트](ENGINE-NOTES.md)에 있습니다.

디스플레이가 있는 환경에서 아래 명령은 각각 30프레임을 렌더링하고 미리보기 PNG를 저장한 뒤 종료합니다. 스모크 테스트는 기존 저장 파일을 불러오거나 덮어쓰지 않습니다.

```bash
dotnet run -c Release -- --smoke-test
dotnet run -c Release -- --palette-smoke-test
dotnet run -c Release -- --showcase-smoke-test
```

| 명령 | 출력 | 내용 |
|---|---|---|
| `--smoke-test` | `smoke-test.png` | 기본 월드와 게임 화면 |
| `--palette-smoke-test` | `palette-preview.png` | 블록 라이브러리 |
| `--showcase-smoke-test` | `blocks-preview.png` | 전체 블록 전시 |

실제 OpenGL 컨텍스트에서 GPU 캐시의 갱신과 수명을 확인하려면 다음 명령을 실행합니다.

```bash
dotnet run -c Release -- --engine-smoke-test
dotnet run -c Release -- --gameplay-smoke-test
```

`--engine-smoke-test`는 정지 장면의 메시 재생성·GPU 업로드가 없는지, 블록 편집과 청크 경계에서 필요한 청크가 갱신되는지, 램프 전원이 외형을 갱신하는지, 청크 제거와 월드 재로딩 시 GPU 자원이 해제되는지 확인하고 `engine-smoke-results.json`에 기록합니다. `--gameplay-smoke-test`는 새 게임플레이 기능을 검증하고 `gameplay-smoke-results.json`과 `gameplay-preview.png`를 만듭니다. 자세한 판정 범위와 측정 결과는 [엔진 노트](ENGINE-NOTES.md)를 확인하세요.

## 배포 빌드

```bash
dotnet publish -c Release -r win-x64 --self-contained true -o dist/windows
python3 package.py
```

패키징 전에 위의 세 기본 미리보기 명령을 실행하세요. `package.py`는 상위 폴더에 `BlockCircuit-windows-x64.zip`과 `BlockCircuit-source.zip`을 만들고 ZIP 무결성을 확인합니다. Windows ZIP에는 실행에 필요한 .NET 런타임, README, 엔진 노트와 라이선스가 포함됩니다. 소스 ZIP에는 하위 폴더를 포함한 모든 C# 소스, 프로젝트 파일, 설명서, 패키징 스크립트, 라이선스와 미리보기 이미지가 포함됩니다. 존재하는 네 측정 JSON도 두 ZIP에 함께 포함하고, `engine-preview.png`·`gameplay-preview.png`는 소스 ZIP에 추가합니다. `bin/`, `obj/`, `dist/`의 소스 파일은 제외합니다.

Raylib는 zlib/libpng 라이선스, Raylib-cs는 zlib 라이선스로 배포됩니다. 라이선스 전문은 `licenses/`에 있고, 코드의 종속성은 프로젝트 파일에 명시되어 있습니다.
